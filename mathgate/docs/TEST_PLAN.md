# TEST_PLAN — сценарии приёмки

Прогоняется вручную на реальном ТВ. Статусы: `не проверено` / `проходит` / `падает`.

| ID | Сценарий | Ожидание | Статус |
|---|---|---|---|
| A1 | Смотреть YouTube 15 минут непрерывно | Пауза, показ примера | проходит |
| A2 | Решить пример правильно | Блок снят, счётчик с нуля | проходит |
| A3 | Ответить неправильно | Блок остаётся, новый пример, пауза | проходит |
| A4 | BACK / HOME / повторный запуск YouTube при блоке | Блок возвращается | проходит |
| A5 | 10 мин → закрыть YouTube → открыть → 5 мин | Блок на суммарных 15 мин | проходит |
| A6 | Смена даты/времени на ТВ | Счётчик не меняется | проходит |
| A7 | 10 мин → выключить ТВ → включить через час → 5 мин | Блок на 15 мин | проходит |
| A8 | Блок активен, выключить и включить ТВ | YouTube всё ещё заблокирован | проходит |
| A9 | Полное отключение питания при блоке (`resetOnPowerLoss=false`) | Блок сохраняется | проходит |
| A10 | То же при `resetOnPowerLoss=true` | Состояние сброшено | проходит |
| A11 | Выключить accessibility-сервис в настройках | Сервис возвращается за секунды | проходит |
| A12 | `adb shell am force-stop <pkg>` во время `Counting` | Сервис поднимается, время восстановлено | проходит |
| A13 | PIN + «Разблокировать сейчас» | Блок снят, статистика записана | не проверено |
| A14 | 5 неверных PIN подряд | Нарастающая задержка | не проверено |
| A15 | Лимит достигнут при активном YouTube (Android 12) | Блок появляется без участия пользователя | не проверено |
| A16 | После обновления YouTube | A1–A5 проходят, версия записана | не проверено |

Примечания по проверке:

- A1–A6 пройдены в фазе 5 (лимиты временно снижались до 60 с / 20 с, затем возвращены).
- A7–A10 — механизм проверен в фазе 6 реальной перезагрузкой ТВ; «потеря питания» имитировалась
  `am force-stop` перед ребутом (чтобы не записался `clean_shutdown=true`). Точная многочасовая
  выдержка A7 и выключение пультом отдельно не прогонялись.
- A11–A12 — проверены в фазе 6 напрямую (см. `DEVICE_NOTES.md`, «Наблюдения фазы 6»).
